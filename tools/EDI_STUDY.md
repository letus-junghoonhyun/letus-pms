# AJ EDI 공부 노트 (2026-09-30 ~ 10-01)

EDI(`edi.ajuprs.com`)를 읽기 전용으로 살펴본 결과와, PMS에 어떻게 활용할지 정리한 문서입니다.

## 1. 접속·인증
- 로그인에 **SMS 인증번호**가 있어 서버가 대신 로그인할 수 없다 → 담당자가 로그인하면 브라우저 스크립트가 동작하는 방식.
- IE/ActiveX 전용이라는 매뉴얼과 달리, 화면이 쓰는 조회 주소는 일반 POST(XML 응답)라 크롬에서 그대로 호출된다.
- 계정: 작업장코드 `P156063 (주)레터스(맵핑금지)`, 사용자 ID는 화면 HTML(`instEmpn`)에 있다.
- 작업장코드(`demdCode`)는 HTML 속성이 아니라 페이지 스크립트 문장 `$("#demdCode").val('…')` 안에 있다.

## 3. 핵심 발견
1. **"모든작업장" 건별 이동은 하루치가 9초, 요청 1번**(9/29: 279건, 양지와 무관한 이동 79건 포함). 작업장을 하나씩 돌 필요가 없다 → 매일 증분 동기화에 적합.
2. 재고조회는 작업장별로만 나오고(합계는 "모든작업장"으로 1번), 한 번에 20초 이상 걸릴 때가 있다 → 470곳 전체를 매일 돌리면 비효율. 이동 내역에서 작업장별 재고를 추정(전일재고 + 받음 − 보냄)하는 방식이 더 가볍다.
3. 입고확인은 대부분 **미확인**(9/29: 271/279). AJ 운영상 "미승인은 승인 안 해도 됨"이라 EDI 확인 상태는 신뢰 지표가 아니다 → PMS의 2단계 확인(사진·서명)이 대체 가치.
4. 이동 건의 **수정·정정**(음수 수량, 신규/수정 표시)이 매일 섞여 있다 → 이력은 upsert로 갱신, 최근 3일은 매번 다시 받는다.
5. 마이너스 재고가 흔하다(양지 18F 9월 중 −7,055). 정산 계산 시 0 처리 여부가 금액을 크게 바꾼다(9월 18F 약 632만원 vs 80만원) → AJ 청구 기준 확인 필요.
6. 재고 수식: 전일 + 렌탈입고 + 이동입고 − 이동출고 − 반납/회수 = 금일 (저장값으로 검증됨).

## 4. 앞으로 연결할 후보 (우선순위 제안)
1. **대사 화면**: EDI 재고 vs PMS 센터 재고 차이(양지), 원인 후보 자동 표시.
2. **이동 → 재고 추정**: 이동 내역만으로 작업장별 일별 재고를 추정해 470곳 조회 없이 정산 계산.
3. **출고 등록 엑셀 자동 생성**: PMS 출고 → AJ 업로드 양식.
4. **납품전표 연계**: 차량번호·기사 정보를 PMS 출고 전표와 매칭.
5. **상이내역·수정요청 상태 연동**: 수량상이 해결 상태를 EDI와 맞춤.
6. **무료 사용 업체 식별**: 이동·보유 데이터로 청구 대상 vs 무료 업체 구분(청구 누락 방지).
