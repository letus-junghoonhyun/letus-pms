## 1. 요약

1. **EDI 데이터를 재고의 기준(원장)으로 삼는 구조가 완성됐어요.** 3개 계정(14C·18F / 일반유형 11A·15A / 23E)을 로그인만으로 매일 받고, 산식 오류 0건, 작업장합 = 전체합계 일치(14C 매일 정확히 일치)까지 검증했어요.
2. **우리 데이터로 AJ 임차료를 재현할 수 있어요.** 14C·18F 구내용 추정 7,354만원/월 vs 9월 명세서 7,673만원(약 96%).
3. **센터 보유분이 비용의 대부분이에요.** 센터 평균 보유 14C 22,743장 + 18F 35,206장 ≈ 58,000장. 이 물량은 청구되지 않는데 AJ 구내용(43원/장·일)은 그대로 나가요. 전산-실물 차이(가짜 재고)를 줄이는 것이 가장 큰 절감 포인트예요.
4. **정산 규칙 확인이 필요한 곳이 생겼어요.** 11A·15A는 (주)시디즈 +4,951장 / (주)일룸 −6,397장처럼 브랜드 작업장끼리 상쇄되는데, "마이너스 0 처리" 규칙 때문에 시디즈 11A가 월 6,535만원으로 계산돼요. 실제 청구 기준 확인 전까지는 이 금액을 쓰면 안 돼요.
5. **PMS → EDI 반영(쓰기)은 가능하지만 단계적으로** 가는 것을 추천해요: 엑셀 생성 → 반자동 입력(사람이 최종 확인) → AJ 공식 연동.

## 5. PMS → EDI 반영(쓰기) 분석

현재 방식: EDI **이동조회/관리 → 추가 → 거래처 검색·선택 → 일자·제품·수량·차량번호 → 확인**을 손으로 입력.

| 방식 | 방법 | 장점 | 위험·제약 | 추천 |
|---|---|---|---|---|
| A. 엑셀 업로드 | PMS가 EDI 업로드 양식 엑셀을 만들어 주고, EDI에서 업로드 | AJ가 제공하는 공식 기능, 위험 낮음 | 우리 계정에서 업로드 버튼(현재 "엑셀업로드(쿠팡)")이 쓸 수 있는지, 자료실 양식(2014) 확인 필요 | **1단계** |
| B. 반자동 입력 | PMS에 "EDI 미반영" 대기열 → EDI 화면에서 스크립트가 추가 행을 자동으로 채움 → **사람이 확인 버튼** → 결과(이동코드)를 PMS에 연결 | 손입력 제거, 사람이 최종 확인, 매칭키(이동코드) 확보 | EDI 입력 화면 구조 분석 필요(읽기 전용으로 분석 가능), 화면 변경 시 수정 필요 | **2단계** |
| C. 완전 자동 | 스크립트가 EDI 저장 요청을 직접 호출 | 가장 빠름 | AJ 승인 없이 자동 기록 → 오류 시 되돌리기 어려움(EDI 삭제 = 수량 0 수정), 정산·전표 영향 | 비추천 (AJ 합의 시에만) |
| D. AJ 공식 연동 | API/파일 연동 협의 | SMS 로그인·세션 문제까지 해결, 가장 안정적 | 협의·개발 기간 | **장기 목표** |

**세션 유지에 대해**: 말씀하신 대로 화면에서 움직임이 있으면 로그인이 유지돼요. 스크립트가 몇 분마다 가벼운 확인 요청을 보내 세션을 유지하고, 탭이 열려 있는 동안 몇 시간마다 자동 재동기화하는 것도 기술적으로 가능해요. 다만 계정당 동시 접속이 1개라서 **3개 계정을 계속 유지하려면 Chrome 프로필 3개**(계정별)가 필요하고, AJ 이용 정책상 문제없는지 확인하는 게 좋아요.

**필요한 준비**
1. 자료실의 "출고 등록 엑셀 업로드 양식" 다운로드(정훈님) → 컬럼 구조 확인
2. EDI 이동 추가 화면의 입력 항목·거래처 코드 체계 분석(읽기 전용, 정훈님이 로그인한 상태에서)
3. PMS 거래처 ↔ EDI 거래처 코드 매핑 확인(작업장 455곳 연결은 완료, 입고처 코드는 이동조회 데이터로 보완)

## 6. 구조 개편 (말씀하신 방향)

1. **작업장 단일 마스터**: 센터와 거래처를 "작업장(위치)" 하나로 합치고 구분(센터/시공팀/업체)만 둔다. EDI와 같은 모델이라 매칭이 쉬워져요.
2. **출고·반납·이동 = 출발지 → 도착지 자유 지정**: 검색 선택창으로 아무 작업장이나 고르고, 방향(출고/반납/이동)은 구분값으로만 남긴다. 권한은 "내가 속한 작업장이 출발지나 도착지인 건"으로 단순화.
3. **재고현황 = EDI 기준 + PMS 미반영분**: 작업장 × 제품 현재고는 EDI 최신값, 그 위에 PMS에 등록됐지만 EDI에 아직 안 잡힌 이동을 "예정"으로 표시.
4. **거래 매칭키**: PMS 거래 ↔ EDI 이동코드 연결. 대사와 반자동 입력의 기반.

## 8. 확인·결정이 필요한 것

1. **11A·15A 청구 기준**: (주)시디즈 +4,951 / (주)일룸 −6,397 상쇄 구조에서 시디즈 청구를 무엇으로 볼지 (마이너스 0 처리 규칙이 이 계정엔 맞지 않을 수 있어요).
2. **15A 청구서가 두 건(일반유형 / 15A 전용)으로 나뉘는 기준** (AJ 문의 예정).
3. **EDI 쓰기 방식**: 1단계 엑셀부터 갈지, AJ에 자동 입력·공식 연동을 같이 문의할지.
4. **세션 유지·주기 동기화** 도입 여부 (Chrome 프로필 3개 운영).
5. **운영 환경**: Supabase 유료 전환 vs 사내 서버 (무료 플랜은 미사용 시 자동 정지).
